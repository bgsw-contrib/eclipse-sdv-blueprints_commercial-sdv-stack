# Integrating with the Eclipse SDV Blueprints Website

This guide is for maintainers publishing the Commercial SDV Stack documentation to the [Eclipse SDV Blueprints website repository](https://github.com/eclipse-sdv-blueprints/blueprints-website). It follows the remote-content approach used by the [E2E Vehicle Signals documentation](https://github.com/eclipse-sdv-blueprints/e2e-vehicle-signals/tree/main/docs/website).

The documentation source stays in this repository. The website fetches it during development or a production build using `docusaurus-plugin-remote-content`. Do not create a separate Docusaurus application here or manually maintain a second copy of the pages.

## Source Pages and Published Routes

| Source in this repository | Website document ID |
| --- | --- |
| `docs/website/introduction.md` | `commercial-sdv-stack/introduction` |
| `docs/website/architecture.md` | `commercial-sdv-stack/architecture` |
| `docs/website/getting-started.md` | `commercial-sdv-stack/getting-started` |
| `docs/website/firmware-update.md` | `commercial-sdv-stack/firmware-update` |
| `docs/website/ecu-configuration.md` | `commercial-sdv-stack/ecu-configuration` |
| `docs/website/api-exploration.md` | `commercial-sdv-stack/api-exploration` |
| `docs/website/troubleshooting.md` | `commercial-sdv-stack/troubleshooting` |

With the current website defaults, the entry route is `/docs/commercial-sdv-stack/introduction`. Neither this maintainer guide nor `docs/README.md` needs to be imported as a public page.

The pages use Docusaurus frontmatter, standard Markdown, and embedded Mermaid diagrams. The website already enables `markdown.mermaid` and `@docusaurus/theme-mermaid`. There are no image files to download or HTML rewriting hooks to configure. Links between pages include `.md` so they work on GitHub and can be resolved to routes by Docusaurus; links to repository files use absolute GitHub URLs.

## 1. Make the Source Available

Merge the documentation into `main` in `eclipse-sdv-blueprints/commercial-sdv-stack` before enabling the production import. Every raw source URL in the plugin's `documents` list must return the intended page, not a 404 response.

For an integration preview before merging, temporarily replace `main` in `sourceBaseUrl` with the documentation branch name or commit SHA. If the source is in a fork, also change the owner and repository. Restore the intended production source before merging the website change. A commit SHA can be used instead of `main` for a pinned release; advancing a pinned source requires another website update.

## 2. Register the Remote Content

In the **website repository**, add this entry to the existing `plugins` array in `docusaurus.config.js`. Preserve the other plugins:

```js
[
  'docusaurus-plugin-remote-content',
  {
    name: 'commercial-sdv-stack',
    sourceBaseUrl:
      'https://raw.githubusercontent.com/eclipse-sdv-blueprints/commercial-sdv-stack/main/docs/website',
    outDir: 'docs/commercial-sdv-stack',
    documents: [
      'introduction.md',
      'architecture.md',
      'getting-started.md',
      'firmware-update.md',
      'ecu-configuration.md',
      'api-exploration.md',
      'troubleshooting.md',
    ],
    requestConfig: { responseType: 'arraybuffer' },
  },
],
```

`name` must be unique among plugin instances. Keep the output directory and document IDs consistent with the sidebar configuration below. No new website dependency is required for this import.

## 3. Add the Sidebar Category

In the **website repository's** `sidebars.js`, add this category to the existing **Blueprints Documentation** category's `items` array inside `overallSidebar`:

```js
{
  type: 'category',
  label: 'Commercial SDV Stack',
  link: { type: 'doc', id: 'commercial-sdv-stack/introduction' },
  items: [
    'commercial-sdv-stack/architecture',
    'commercial-sdv-stack/getting-started',
    'commercial-sdv-stack/firmware-update',
    'commercial-sdv-stack/ecu-configuration',
    'commercial-sdv-stack/api-exploration',
    'commercial-sdv-stack/troubleshooting',
  ],
},
```

The category links directly to Introduction. The six child pages follow the reader's workflow. `sidebar_position` frontmatter also provides an order if the website later adopts autogenerated sidebars.

## 4. Optionally Add a Footer Link

Add an item to the relevant existing `themeConfig.footer.links` group's `items` array in `docusaurus.config.js`:

```js
{
  label: 'Commercial SDV Stack',
  to: '/docs/commercial-sdv-stack/introduction',
},
```

A homepage entry is optional. If one is desired, follow the current implementation in the website's `src/pages/index.tsx`; do not assume a `BlueprintCard` component exists. Point the documentation link to the same entry route and retain a separate source repository link where appropriate.

## 5. Build and Preview

Work in a checkout of the website, not in this blueprint repository. Use a Node.js version compatible with its `package.json` and the package manager used by its CI (currently Yarn with `yarn.lock`):

```bash
git clone https://github.com/eclipse-sdv-blueprints/blueprints-website.git
cd blueprints-website
mkdir -p docs
yarn install --frozen-lockfile
```

Apply the plugin and sidebar changes above, then run:

```bash
yarn build
yarn serve --host 127.0.0.1 --port 3000
```

Open http://localhost:3000/docs/commercial-sdv-stack/introduction. If port 3000 is occupied by the blueprint's Symphony Portal, use `--port 3001` and open the corresponding URL instead.

For iterative documentation work, `yarn start --host 127.0.0.1 --port 3001` is also available. Restart the website process to refetch changed remote content. Source changes do not update an already published static site until the website is rebuilt and deployed.

### Preview Unpublished Local Pages

To preview this checkout without pushing a branch, apply the sidebar change but **temporarily omit only the new Commercial SDV Stack remote-content plugin entry**. Otherwise it would overwrite the local pages with remote content or fail if the source is not yet published.

From the website checkout, copy the pages (adjust the source path to your checkout):

```bash
mkdir -p docs/commercial-sdv-stack
cp /workspaces/commercial-sdv-stack/docs/website/*.md docs/commercial-sdv-stack/
yarn build
yarn serve --host 127.0.0.1 --port 3001
```

Do not commit these generated/copied pages to the website. Restore the plugin configuration before submitting the website integration change. This local-copy check verifies rendering and navigation, but does not verify that the production remote URLs are available.

## 6. Publication Checklist

- [ ] All seven pages are available at the configured raw source URLs.
- [ ] The plugin document list matches the source filenames, including case.
- [ ] The sidebar category and every child page resolve without missing document IDs.
- [ ] The production build succeeds; inspect warnings as well as the exit code. The website currently warns rather than fails on some broken links.
- [ ] The entry page is reachable at `/docs/commercial-sdv-stack/introduction`.
- [ ] Previous/next navigation, relative page links, and section anchors work.
- [ ] Architecture and both sequence diagrams render, including at narrow viewport widths.
- [ ] Commands, tables, and code blocks remain readable on desktop and mobile.
- [ ] The firmware simulation limitation and development-only security notes are visible.
- [ ] No copied pages, temporary source URLs, local paths in site configuration, or unrelated website changes are included in the website pull request.

Submit the website configuration changes in a separate pull request to `blueprints-website`. This repository supplies the content and instructions; it does not itself register or deploy pages on the central website. After the website PR is merged and its deployment succeeds, verify the published page at https://sdv-blueprints.eclipse.dev/docs/commercial-sdv-stack/introduction.

## Maintenance

When adding or renaming a page, update the remote plugin's `documents` list, sidebar IDs, internal links, and this inventory together. Keep source-code links absolute so moving pages into the website's `docs/commercial-sdv-stack` directory does not break repository references. Rebuild the website after documentation changes to publish them.
